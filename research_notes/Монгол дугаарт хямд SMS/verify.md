# Verify.mn болон Монголын дүрэм: вэбээс хэрэглэгчийн утас руу SMS илгээх

Эх сурвалжийг 2026-10-14-нд уншсан. Verify.mn-ийн нийтийн API-г [нүүр хуудас](https://www.verify.mn/), [үйлчилгээний нөхцөл](https://www.verify.mn/terms/) (хүчин төгөлдөр 2026-04-22), [нууцлалын бодлого](https://www.verify.mn/privacy/) (хүчин төгөлдөр 2026-04-14)-оос авав. `https://verify.mn/app/docs/` хуудас энэ уншилтад гарчигнаас өөр endpoint текст буцаагаагүй (аппын хоосон бүрхүүл). Доорх endpoint-ууд нүүр хуудсын нийтийн баримт бичиг болон тэнд байрлуулсан интеграцийн зааварт байгаа.

## Verify.mn-ийн албан ёсны баримт бичиг утас руу SMS илгээх API санал болгодог уу, эсвэл зөвхөн хэрэглэгч өөрөө shortcode руу бичдэг MO баталгаажуулалт уу?

### Takeaway
Нийтийн баримт бичиг зөвхөн MO урсгалыг заасан: хэрэглэгч өөрийн дугаараас 144773 руу SMS илгээнэ, Verify.mn түүнийг backend event болгоно. Серверээс хэрэглэгчийн дугаар руу дурын мэдэгдэл илгээх endpoint байхгүй.

### Cited Findings
- Verify.mn өөрийгөө «SMS → Backend Event API» гэж тодорхойлж, «144773 руу ирсэн SMS-г real-time event болгож таны backend руу шууд илгээнэ» гэж бичсэн. — [Verify.mn](https://www.verify.mn/)
- Үйлчилгээний нөхцөл: «Verify.MN нь Монгол Улсын хөгжүүлэгчдэд зориулсан MO SMS баталгаажуулалтын API үйлчилгээ». — [Үйлчилгээний нөхцөл](https://www.verify.mn/terms/)
- Нүүр хуудас MT ба MO-г тусад нь харьцуулсан. MT (Mobile-Terminated): урсгал Server → User, зардлыг илгээгч төлнө, хэрэглээ нь «OTP, Notification». MO (Mobile-Originated): урсгал User → Server, зардлыг хэрэглэгч төлнө, хэрэглээ нь «Verification, Payment, Trigger». Гарчиг нь «Илгээх биш, хүлээн авах — MO SMS гэж юу вэ?». — [Verify.mn](https://www.verify.mn/)
- Баримтжуулсан session урсгал: backend `POST https://api.verify.mn/sessions` дуудна; хариунд `sessionId`, `shortcode` (`144773`), `text`, `smsUri` (`sms:144773?body=...`), `displayInstruction`, `expiresAt` ирнэ; хэрэглэгч өөрийн дугаараас тухайн текстээ 144773 руу илгээнэ; дараа нь `GET /sessions/{sessionId}` дээр `sessionStatus` нь `PENDING`, `VERIFIED`, эсвэл `EXPIRED` болно. — [Verify.mn](https://www.verify.mn/)
- `POST /sessions` body: `phone` (8–16 орон), `text` (1–120 тэмдэгт), заавал биш `callback` (https URL), заавал биш `responseSms`. Алдаа: 400, 401, 409 (ижил утас+текст дээр идэвхтэй session), 500. `GET /sessions/{sessionId}` нь auth шаардахгүй. Callback нь GET, body байхгүй. — [Verify.mn](https://www.verify.mn/)
- `responseSms` нь хэрэглэгч SMS илгээсний дараах хариу мессеж. Дээд тал нь 160 ASCII тэмдэгт. Орхивол анхдагч текст нь `Tany medeelliig huleen avlaa`. Оператороос хамаарна: Unitel зөвхөн анхдагч хариуг хүргэнэ, захиалгат текстийг хүргэхгүй; Lime хариу SMS огт хүргэхгүй. Баталгаажуулалтыг хариу SMS-ээр биш, `sessionStatus`-аар UI дээр харуулахыг зааварласан. — [Verify.mn](https://www.verify.mn/)
- Хоёр дахь загвар нь SESSION биш RULE: хөгжүүлэгч console-оос prefix үүсгэж, хэрэглэгч 144773 руу `PREFIX:текст` илгээнэ, callback руу query параметр бүхий GET очно. Энэ нь мөн ирж буй SMS. — [Verify.mn](https://www.verify.mn/)
- Дэмжих оператор: Mobicom, Skytel, Unitel, G-Mobile, ONDO, Lime, Toki, Kaos. Session TTL-ийг нүүр хуудас 5 минут, интеграцийн заавар 300 секунд гэж бичсэн. — [Verify.mn](https://www.verify.mn/)
- Нууцлалын бодлого SMS-ийг «хүргэхдээ» гуравдагч SMS gateway ашиглана гэж бичсэн боловч энэ өгүүлбэр баталгаажуулалтын урсгалын хажууд байгаа бөгөөд илгээх endpoint нэмээгүй. Цуглуулах өгөгдөл: эцсийн хэрэглэгчийн дугаар, session ID, SMS-ийн агуулга, callback URL, хариуны лог. — [Нууцлалын бодлого](https://www.verify.mn/privacy/)
- Нэг хуудсан дээр зөрүүтэй аюулгүй байдлын тайлбар байна. FAQ: callback-ийг нэмэлт secret, JWT HS256-аар баталгаажуулж болно. Интеграцийн заавар: callback нь GET, body байхгүй, HMAC байхгүй, зөвхөн сэрээх дохио; төлөвийг `GET /sessions/{sessionId}`-аар дахин шалгана. — [Verify.mn](https://www.verify.mn/)

### Inferences
- `POST /sessions` нь хэрэглэгч рүү код илгээх дуудлага биш. Энэ нь «энэ дугаар энэ текстийг 144773 руу илгээнэ» гэсэн хүлээлтийн бүртгэл үүсгэнэ.
- `responseSms` нь шинэ ангийн мэдэгдэл илгээх суваг биш. Хэрэглэгч эхлээд төлбөртэй SMS илгээсний дараа л, оператороос хамаарч, богино ASCII хариу очих эсэх нь тодорхойгүй.
- Нээлттэй баримтад `POST /messages`, `POST /sms` зэрэг MT илгээлтийн зам байхгүй. MT-г Verify.mn өөрсдөө «илгээх» гэж нэрлээд, өөрийн бүтээгдэхүүнээс тусгаарласан.

### Gaps
- Нэвтэрсэн developer console (`/app/docs/` болон бусад хаалттай хуудас)-ыг нээж үзээгүй. Нийтийн хуудсанд байхгүй MT API тэнд нуугдаж байж болно гэсэн баримт олдсонгүй; бас «байхгүй» гэж console-оор баталгаажуулаагүй.
- Орлогын хуваарилалтын хувь (оператор, татвар, платформ) нүүр хуудсын «1 SMS = 150₮» хэсэгт тоо болон хувиар бүрэн гараагүй. Зөвхөн 40₮-ийн хөгжүүлэгчийн орлого тоогоор гарсан.

## Session хэдэн төгрөг вэ, нийтлэгдсэн үү?

### Takeaway
Хөгжүүлэгчээс session тутам авах үнэ нийтлэгдээгүй. Нийтлэгдсэн эдийн засаг: setup 0₮, сарын хураамж 0₮; хэрэглэгч 144773 руу илгээх SMS бүрт одоогоор 150₮ төлнө; амжилттай баталгаажуулалт буюу SMS event бүрт хөгжүүлэгчид 40₮ орлого орно.

### Cited Findings
- «0₮ зардал. SMS төлбөрийг хэрэглэгч өөрөө төлнө. Барьцаа төлбөр, суурь хураамж, setup fee, monthly fee ямар ч зардал гарахгүй.» FAQ: setup fee байхгүй, monthly fee байхгүй, SMS event бүрт хөгжүүлэгчийн дансанд 40₮. — [Verify.mn](https://www.verify.mn/)
- Нөхцөл: хөгжүүлэгч setup fee болон сарын төлбөр төлөхгүй. «SMS баталгаажуулалт амжилттай болох бүрд» дансанд 40₮. Орлогыг сар бүрийн 5-ны дотор өмнөх сарын тооцоогоор, профайл дахь банкны данс руу шилжүүлнэ. — [Үйлчилгээний нөхцөл](https://www.verify.mn/terms/)
- 144773 нь нэмүү өртөгт тусгай дугаар. «Энэ дугаар руу илгээсэн SMS-д тухайн цаг үеийн тарифаар (одоогоор 150₮) төлбөр эцсийн хэрэглэгчид ногдоно.» Хөгжүүлэгч SMS илгээх товч, заавар, `smsUri`-г харуулахаасаа өмнө тарифыг тодорхой мэдэгдэнэ. Мэдэгдээгүйгээс гарсан нэхэмжлэлийг хөгжүүлэгч хариуцна. — [Үйлчилгээний нөхцөл](https://www.verify.mn/terms/)
- Интеграцийн заавар: «Every SMS to 144773 costs the user 150₮, matched or not.» «Per verified phone: user pays 150₮ to operator; developer earns 40₮.» — [Verify.mn](https://www.verify.mn/)
- Нүүр хуудасны маркетингийн мөр «SMS бүр = 40₮ орлого» болон «баталгаажуулалт хийх бүрд» гэсэн үг нөхцөлийн «амжилттай болох бүрд»-тэй яг ижил биш. Таарахгүй SMS мөн хэрэглэгчид 150₮ болно гэж интеграцийн заавар бичсэн; тэр үед 40₮ орно гэж нөхцөл шууд хэлээгүй. — [Verify.mn](https://www.verify.mn/); [Үйлчилгээний нөхцөл](https://www.verify.mn/terms/)

### Inferences
- CinemaFeel-ийн Verify.mn нэвтрэлт нь платформд SMS илгээх зардал үүсгэхгүй. Зардал хэрэглэгч дээр, 150₮/илгээлт.
- Шинэ анги бүрийг энэ сувгаар «мэдэгдэх» гэж оролдвол хэрэглэгч өөрөө мессеж бичиж, бүрт 150₮ төлнө. Энэ нь вэбээс түлхэх мэдэгдлийн үнэ биш.

### Gaps
- 150₮ нь «одоогоор» гэсэн тариф. Өөрчлөгдөх огноо, НӨАТ орсон эсэх, оператор тус бүрийн ялгаа нийтлэгдээгүй.
- 40₮ нь таарсан session-д олгогддог уу, 144773 руу ирсэн SMS бүрт олгогддог уу гэдэгт нүүр хуудас ба нөхцөл үгээр зөрсөн. Албан ёсны нэгдсэн тарифын хүснэгт олдсонгүй.

## Монголд гадагш мэдэгдлийн SMS илгээхэд урьдчилсан зөвшөөрөл хэрэгтэй юу, илгээгч оператор эсвэл ХХЗХ-д бүртгэлтэй байх ёстой юу?

### Takeaway
Утасны дугаар нь хувийн мэдээлэл. Хувийн хэвшлийн мэдээлэл хариуцагч түүнийг цуглуулж, ашиглахад мэдээллийн эзний цаасан эсвэл цахим зөвшөөрөл хэрэгтэй. Нэвтрэлтийн зорилгоос өөр зорилгоор (шинэ ангийн мэдэгдэл) ашиглахад дахин зөвшөөрөл авна. Тусгай богино дугаар (14xxxx/15xxxx, 13xxxx) нь ХХЗХ-ийн дугаарлалтаар, тусгай зөвшөөрөлтэй мессежийн үйлчлэгчээр дамжина. Вэбсайт энгийн мэдэгдлийн sender ID-г ХХЗХ-д тусад нь бүртгүүлэх ёстой гэсэн нийтийн дүрэм энэ хайлтад олдсонгүй.

### Cited Findings
- Хүний хувийн мэдээлэл хамгаалах тухай хууль (шинэчилсэн найруулга, 2021 оны 12 дугаар сарын 17). «Цахим тодорхойлогч»-д харилцаа холбооны утастай болон утасгүй технологийн хаяг орно (4.1.14). «Хүний хувийн мэдээлэл»-д цахим тодорхойлогч болон хүнийг шууд бусаар тодорхойлох бусад мэдээлэл орно (4.1.11). — [legalinfo.mn, хуулийн эх](https://legalinfo.mn/mn/detail?lawId=16390288615991); мөн [parliament.mn файл](https://www.parliament.mn/files/6e3aa61137c5466da1445df9c52fed33/?d=1)
- Төрийн байгууллагаас бусад хүн, хуулийн этгээд мэдээллийг мэдээллийн эзний зөвшөөрлөөр, хуульд заасан үндэслэлээр, хөдөлмөрийн харилцаа, эсвэл гэрээний хэрэгжилтийн үндэслэлээр цуглуулж, боловсруулж, ашиглана (7.1, 6.1.1–6.1.4). Мэдээлэл хариуцагч хуульд зааснаас бусад тохиолдолд зөвшөөрөл авна (8.1). — [parliament.mn файл](https://www.parliament.mn/files/6e3aa61137c5466da1445df9c52fed33/?d=1)
- Зөвшөөрөлд зорилго, хариуцагчийн нэр, мэдээллийн жагсаалт, хугацаа, нийтэд ил болгох эсэх, бусдад дамжуулах эсэх ба дамжуулах этгээд, цуцлах хэлбэр байна (8.2). Зөвшөөрөл цаасан эсвэл цахим хэлбэртэй бичгээр (8.3). Цахим зөвшөөрөл нь хүлээн зөвшөөрсөн аргаар тухайн хүнийг таньж, баталгаажуулсан байна (8.4). Хариу өгөөгүй, хугацаа өнгөрсөн нь зөвшөөрөл биш (8.6). Зөвшөөрлийг хэдийд ч цуцалж болно (8.7). Хариуцагч зөвшөөрөлтэй болохоо нотолно (8.9). Анхны зорилгоос өөр зорилгоор ашиглахад дахин зөвшөөрөл авна (8.10). 8.2.6-д тусгаагүй бол бусдад дамжуулахад тусдаа зөвшөөрөл (8.11). — [parliament.mn файл](https://www.parliament.mn/files/6e3aa61137c5466da1445df9c52fed33/?d=1)
- «Захидал харилцааны мэдээлэл» нь захидал, илгээмж, цахим шуудан, харилцаа холбоогоор солилцож байгаа мэдээлэл (4.1.4) бөгөөд эмзэг мэдээлэлд орно (4.1.12). Энэ заалт харилцааны агуулгыг цуглуулах тухай. Утасны дугаар руу мэдэгдэл илгээх нь энэ эмзэг ангилалд шууд орно гэсэн ХХЗХ-ийн тайлбар олдсонгүй. — [parliament.mn файл](https://www.parliament.mn/files/6e3aa61137c5466da1445df9c52fed33/?d=1)
- ХХЗХ-ийн «Харилцаа холбооны сүлжээний дугаарын ашиглалт, үйлчилгээг бүртгэхтэй холбогдсон журам» (2021-12-17, дараа нь 2023 оны 03 дугаар сарын 30-ны 30 дугаар тогтоол, 2025 оны 02 дугаар сарын 13-ны 40 дугаар тогтоолоор зарим хэсэг хүчингүй). Мессежид суурилсан нэмүү өртөгт лавлахад `14xxxx`/`15xxxx`, хэрэглэгчийн тарифт эсвэл төлбөргүй мессежид `13xxxx` (3.1.3). Тусгай дугаарт мессежийн дугаарыг «Мэдээллийн сүлжээ ашиглах, үйлчилгээ эрхлэх» тусгай зөвшөөрөлтэй үйлчлэгчид хуваарилж, тэр нь цааш хэрэглэгчид нэг бүрчлэн олгоно (4.10, 4.16, 5.4.1). Үйлчлэгч дотоод журмаа ХХЗХ-аар хянуулж, бүртгэлийн хураамж, барьцаа, суурь хураамж, орлого хуваарилалтыг тусгана (5.4.3). Нэмүү өртөгт мессежийн үйлчилгээг 16-аас доош насны хүүхдэд үзүүлэхгүй (5.4.6). — [legalinfo.mn, дугаарлалтын журам](https://legalinfo.mn/mn/detail?lawId=16389995447231&showType=1)
- ХХЗХ-ийн одоогийн хүсэлтийн хуудас: тусгай дугаараар мэдээлэл, лавлах үйлчилгээ үзүүлэх бол дээрх журамтай танилцаж, `customer.crc.gov.mn`-ээр өргөдөл гаргана. Шийдвэрлэх хугацаа ажлын 10–20 хоног. Энэ хуудас вэбсайтын мэдэгдлийн sender ID-ийн тухай биш, тусгай дугаар эзэмших тухай. — [Тусгай дугаар шинээр авах](https://www.crc.gov.mn/for-new-license-applicants/burtgeliin-gercilgee/tusgai-dugaar-sineer-avax)
- `smsnumber.mn` нь 2009 оны 05 дугаар сарын 15-ны ХХЗХ-ийн шийдвэр, 2009 оны 05 дугаар сарын 27-ны операторуудын санамж бичгийг иш татсан хуучин хуудас. Тэндхийн үйлчилгээ нь «SMS-ээр мэдээлэл хүлээн авах», өөрөөр хэлбэл тусгай дугаар руу ирэх MO. Бүртгэлийн хураамж (энгийн дугаар 90,000₮ гэх мэт), суурь 20,000₮, барьцаа 60,000₮, `15xxxx` ангиллын 150–550 нэгж зэрэг тоо энэ хуудсан дээр байгаа боловч одоогийн ХХЗХ-ийн тариф гэж батлагдаагүй. — [smsnumber.mn](http://www.smsnumber.mn/)
- Зар сурталчилгааны тухай хуулийн уншсан эхэд SMS, мессежээр урьдчилан зөвшөөрөл авах тусдаа заалт байхгүй. 12.1 нь бусдын вэб хуудсанд зөвшөөрөлгүй зар байрлуулахыг хориглоно. — [Wikisource, Зар сурталчилгааны тухай хууль](https://wikisource.org/wiki/%D0%9C%D0%BE%D0%BD%D0%B3%D0%BE%D0%BB_%D0%A3%D0%BB%D1%81%D1%8B%D0%BD_%D0%97%D0%B0%D1%80_%D1%81%D1%83%D1%80%D1%82%D0%B0%D0%BB%D1%87%D0%B8%D0%BB%D0%B3%D0%B0%D0%B0%D0%BD%D1%8B_%D1%82%D1%83%D1%85%D0%B0%D0%B9_%D1%85%D1%83%D1%83%D0%BB%D1%8C)
- Verify.mn-ийн нөхцөл хөгжүүлэгчийг хэрэглэгчийг хууран мэхлэх, зөвшөөрөлгүйгээр SMS төлбөр тооцуулах, phishing-д ашиглахыг хориглоно. — [Үйлчилгээний нөхцөл](https://www.verify.mn/terms/)

### Inferences
- Утасны нэвтрэлтээр дугаар авсан нь шинэ ангийн SMS илгээх зөвшөөрөл биш. 8.10-ын дагуу зорилго өөр бол дахин зөвшөөрөл хэрэгтэй. Зөвшөөрөлд зорилго (ангийн мэдэгдэл), цуцлах арга, хэрэв SMS gateway-д дугаар дамжуулах бол тэр этгээд багтсан байна.
- Дуугүй өнгөрөөсөн хэрэглэгчийг зөвшөөрсөн гэж тооцохгүй (8.6).
- 144773 дээрх баталгаажуулалт нь нэмүү өртөгт тусгай дугаарын үйлчилгээ. Түүнийг 16-аас доош насныханд үзүүлэхгүй гэсэн журмын 5.4.6 нь дугаар эзэмшигч/үйлчлэгчид хамаарах шаардлага. Verify.mn өөрсдөө операторуудтай 144773-ын гэрээтэй гэж бичсэн тул CinemaFeel тусдаа shortcode авах шаардлагатай гэж нөхцөлд байхгүй. — [Verify.mn](https://www.verify.mn/)
- Гадагш мэдэгдэл илгээхийн тулд тусдаа MT/A2P суваг хэрэгтэй. Тэр суваг богино дугаар ашиглавал дугаарын эрх нь ХХЗХ-ийн журмаар тусгай зөвшөөрөлтэй мессежийн үйлчлэгч дээр байна. Альфа нэр (sender ID)-ийг операторт бүртгүүлэх журмыг энэ хайлт ХХЗХ-ийн нийтийн хуудаснаас олсонгүй.

### Gaps
- ХХЗХ-ийн сайт дээр «спам SMS», «хүсээгүй мессеж», «мэдэгдлийн SMS-д урьдчилсан зөвшөөрөл» гэсэн тусдаа нийтийн журам олдсонгүй. Зөвшөөрлийн хамгийн тодорхой эх нь хувийн мэдээллийн хууль.
- Mobicom, Unitel, Skytel, G-Mobile-ийн A2P гэрээ, sender ID бүртгэл, нэгж үнэ энэ даалгаврын хүрээнд операторын албан хуудаснаас баталгаажаагүй.
- Гэрээний үндэслэл (7.1.1 → 6.1.4) нь нэвтрэлтийн дугаарыг мэдэгдэлд ашиглахыг чөлөөлөх эсэхийг шүүхийн эсвэл ХХЗХ-ийн тайлбар олдсонгүй. 8.10 дахин зөвшөөрлийг ерөнхийд нь шаардсан хэвээр.
- Зар сурталчилгааны хуулийг SMS opt-in байгаа эсэхээр хайсан; тусдаа заалт олдсонгүй. Хуулийн бүх нэмэлтийг мөр мөрөөр тулгаагүй.

## Практик хил: Verify.mn утасны нэвтрэлт дангаараа шинэ ангийн мэдэгдэл болж чадахгүй

### Takeaway
CinemaFeel Verify.mn-ээр хэрэглэгчийг таньж болно. Тэр холболт хэрэглэгчийн утас руу «шинэ анги гарлаа» гэж түлхэх SMS болж хувирахгүй. Мэдэгдэлд тусдаа MT суваг, тусдаа зорилгын зөвшөөрөл хэрэгтэй.

### Cited Findings
- Баталгаажуулалтын алхам: сервер session үүсгэнэ, хэрэглэгч 144773 руу өөрөө илгээнэ, сервер зөвхөн ирсэн эсэхийг шалгана. — [Verify.mn](https://www.verify.mn/)
- MT-г Verify.mn «OTP, Notification» гэж жишээлсэн боловч өөрийн API-г «илгээх биш, хүлээн авах» гэж нэрлэсэн. — [Verify.mn](https://www.verify.mn/)
- `responseSms` нь тухайн ирсэн SMS-ийн хариу бөгөөд Unitel захиалгат текстийг хүргэхгүй, Lime хариу илгээхгүй. — [Verify.mn](https://www.verify.mn/)
- 144773 руу илгээсэн SMS бүрт хэрэглэгч одоогоор 150₮ төлнө. Үнийг илгээх товчноос өмнө мэдэгдэх үүрэгтэй. — [Үйлчилгээний нөхцөл](https://www.verify.mn/terms/)
- Анхны зорилгоос өөрөөр дугаарыг ашиглахад дахин зөвшөөрөл (8.10). — [parliament.mn файл](https://www.parliament.mn/files/6e3aa61137c5466da1445df9c52fed33/?d=1)

### Inferences
- Нэвтэрсэн дугаарын сан нь мэдэгдлийн жагсаалт биш. Шинэ ангийн SMS явуулахын өмнө хэрэглэгч тухайн зорилгыг таньж баталгаажуулсан цахим зөвшөөрөл өгсөн байх, цуцлах боломжтой байх ёстой.
- Verify.mn-ийн 40₮ нь платформын орлого болохоос хэрэглэгч рүү үнэгүй мэдэгдэл илгээх эрх биш.
- Хэрэв дараа нь гадагш SMS нэмбэл тээвэрлэгч нь Verify.mn-ийн session API байж болохгүй. Тусгай дугаар ашиглавал дугаарын эрх нь тусгай зөвшөөрөлтэй мессежийн үйлчлэгч дээр байна.

### Gaps
- Монголд вэбсайтад хямд MT мэдэгдэл зардаг, ХХЗХ-ийн журамд нийцсэн бэлэн API энэ тэмдэглэлд багтаагүй. Энэ асуулт зөвхөн Verify.mn болон зөвшөөрөл/бүртгэлийн хил.
